Secure Login Service (SLS)

Content Security Policy (CSP) Support

  • Support for setting a “Content Security Policy” has been added. NOTE: If a CSP is configured, existing JSP files might not properly work anymore if they contain embedded scripts, event handlers or styles. Please consult the new chapter in the SLS Administration Guide for details about configuration and how to migrate existing JSPs.

Improved support for signed JSON Web Tokens (JWTs)

  • It is now possible to create signed JSON Web Tokens (JWTs), signed either with an HMAC (HS256, HS384 and HS512) or with RSA (RS256, RS384 and RS512). JWT signatures can now be verified in additional ways, including verification via the same properties as used to create and sign, or via a JWKS (JSON Web Key Set) as often published by the JWT issuer. See the chapter “JSON Web Tokens” in the SLS Administation Guide and the jwt.* scripting functions in the SLS Scripting Guide for more details.

Tomcat 10 Support

  • A new webapp has been added, “sls-webapp-complete-jakarta”, which is ready to be deployed in a Tomcat 10 servlet container.

Various Improvements and Fixes

  • Added new script function function.getActualFile() which returns a file object pointing to a file specified with a path which is either relative to the SLS web application directory, or absolute.
  • The OIDC OP no longer redirects to the redirect_uri in case of an unknown or missing client_id in the authentication request, in order to prevent attacks that would redirect via the trusted OP domain to an “evil” domain.
  • Added support for using servlet container sessions when used without an HSP.
  • Fixed language selection not working when the browser blacklist feature was used, i.e. no language selection possible for the “UserAgent.jsp”.
